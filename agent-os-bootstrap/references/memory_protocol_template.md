# Learning records

Keep reusable observations in a domain file here when there is evidence worth keeping. Start empty; do not invent examples as company knowledge. Existing memory formats take precedence over this starter format.

Each entry records:

- ID and domain.
- Status: observation, hypothesis, confirmed rule, or contradicted.
- The specific statement and where it applies.
- Source and date; distinguish what happened from the agent's interpretation.
- Owner and a test that could support or contradict the statement.
- Evidence from each independent check, including contradictory results.
- Owner's approval and date before treating it as an operating rule.

Use the relevant confirmed rules during work. At session close, propose a change only when there is new reusable learning. Existing company validation thresholds still apply. Do not count repeated copies of one event as independent evidence, silently change a rule, or add confidential details to shared memory.

Keep a proposed change in the authorized draft location or conversation until approval permits a memory-file update. Contradictory evidence stays attached to the hypothesis pending owner review; do not automatically change its status or discard earlier evidence.
